# 非功能需求文档

## 1. 文档目的

本文规定社区废旧家电一体化管理系统在易用性、性能、可靠性、安全性、兼容性、可维护性和可测试性方面的要求。性能数值为当前设计目标，需结合部署环境和实际测试确认。

## 2. 易用性

1. 页面布局清晰，居民、回收人员和管理员可以按角色快速找到常用功能。
2. 表单应标识必填项，并对缺失、格式错误或不符合业务规则的数据给出明确提示。
3. 订单详情应展示当前状态、预约信息、回收结果和必要的处理记录。
4. 取消、驳回等影响业务的操作应要求用户确认；状态不允许的操作应解释原因。
5. 页面及状态标签使用中文，用户无需理解内部状态编码。

## 3. 性能

1. 在正常部署环境及常见网络条件下，普通页面和查询操作建议在 3 秒内返回。
2. 常见新增、修改和订单状态操作建议在 3 秒内完成响应。
3. 初步按 50 个并发用户作为设计目标，最终以部署环境和测试结果为准。
4. 列表查询应分页；统计查询应支持时间、品类或状态筛选，避免无条件加载大量数据。

## 4. 可靠性

1. 用户、地址、品类、订单、回收结果和评价等业务数据应正确保存并保持关联。
2. 重复提交订单或结果时，系统应提供防重复处理，避免生成重复业务数据。
3. 订单状态必须由后端按业务规则校验，不能跳过必要流程或回退到不允许的状态。
4. 审核、分派、接单、回收结果登记、居民确认和异常处理等操作应可追溯。
5. 服务或数据库发生异常时，应给出可理解的提示，不向用户暴露堆栈或数据库连接等内部信息。
6. 应定期备份数据库，并按实际部署条件确定备份频率及保留周期。

## 5. 安全性

1. 系统应验证登录身份，并按角色和业务数据范围授权。
2. 居民只能访问本人资料、地址和订单；回收人员只能访问分派给本人的任务；管理员可按管理权限访问社区业务数据。
3. 密码不得明文存储，应采用安全的密码哈希方式保存。
4. 服务端必须执行身份、角色、资源归属及订单状态校验，不能仅依赖前端隐藏按钮。
5. 用户输入应进行校验，降低非法输入导致业务异常或数据风险的可能。
6. 用户停用后不得登录或继续执行业务操作。
7. 地址和联系电话等个人信息只应向业务所需角色展示。

## 6. 兼容性

1. 系统应支持约定范围内的主流现代浏览器，如近期稳定版 Chrome、Edge。
2. 页面应适配常见桌面分辨率；若实现移动端页面，应适配常见手机屏幕。
3. 前后端接口采用统一的数据格式和字符编码，状态编码与中文展示分离。

## 7. 可维护性与可扩展性

1. 按账号、品类、地址、订单、回收结果、评价和统计等业务职责划分代码模块。
2. 订单状态、取消条件和角色权限等关键规则应集中实现，避免重复定义。
3. 统一接口响应、异常处理和日志规范。
4. 数据库连接等环境配置应与业务代码分离。
5. 表名和字段名使用英文，表及字段添加中文注释。
6. 设计应允许后续增加品类、状态和统计维度，而不破坏已有历史记录。

## 8. 可用性

1. 登录失败、业务校验失败和服务不可用时应提供明确提示。
2. 页面刷新或重新登录后，用户仍能查询已保存的订单及其状态。
3. 订单提交等关键操作应反馈明确结果，并避免用户因重复点击造成重复记录。
4. 维护或服务暂不可用时，应提示用户稍后重试。

## 9. 可测试性

1. 核心功能应具备可验证的输入、操作步骤和预期结果。
2. 角色权限、订单状态流转、取消规则和居民确认流程应可独立验证。
3. 测试环境应与正式环境区分，测试账号和数据不得误作正式业务数据。
4. 应保留定位问题所需的错误日志和关键操作记录。

## 10. 初步验收指标

| 类别 | 初步验收要求 |
|---|---|
| 易用性 | 三类角色可按页面提示完成核心业务流程 |
| 性能 | 常见查询和操作目标响应时间不超过 3 秒，具体以测试环境为准 |
| 权限 | 越权访问本人以外的订单或任务会被拒绝 |
| 业务可靠性 | 订单状态遵循规定流程，重复提交不生成重复订单 |
| 兼容性 | 约定浏览器中主要功能可正常使用 |
| 可追溯性 | 关键订单操作记录操作人、时间和必要说明 |

> 并发量和响应时间属于初步设计目标，需结合最终软硬件环境进行确认。

# 基于 Spring Boot 的社区废旧家电一体化管理系统功能需求文档

## 1. 引言

### 1.1 编写目的

本文档用于说明社区废旧家电一体化管理系统的功能范围、用户角色、业务流程和主要功能要求，为后续系统设计、开发和验收提供依据。

### 1.2 项目背景

居民处理废旧家电时，通常需要自行寻找回收渠道，预约和进度跟踪不够方便；社区也缺少统一管理回收申请、回收人员和回收记录的工具。本系统面向社区回收业务，提供线上预约、订单审核与分派、上门回收、结果确认和数据查询等功能。

### 1.3 项目目标

- 方便居民查询回收品类并提交上门回收申请。
- 支持社区管理员审核申请并分派回收任务。
- 支持回收人员确认任务、更新处理进度并登记实际回收数量和重量。
- 支持居民确认回收结果后完成订单。
- 为管理员提供用户、回收人员、回收品类、订单和业务统计管理能力。
- 保存订单处理和回收记录，便于查询与追溯。

### 1.4 术语说明

| 术语 | 说明 |
|---|---|
| 居民用户 | 在系统中自行注册并提交回收申请的社区居民 |
| 回收人员 | 由社区管理员维护、负责执行上门回收任务的人员 |
| 社区管理员 | 负责系统日常业务管理的工作人员 |
| 回收订单 | 居民提交的废旧家电回收申请及其处理过程记录 |
| 回收记录 | 回收人员上门后登记的实际回收品类、数量和重量等信息 |

## 2. 系统用户与角色

### 2.1 居民用户

居民用户自行注册账号并登录系统，可以维护个人资料和回收地址、查询回收品类、提交回收申请、查看本人订单进度、取消符合条件的订单、确认回收结果以及评价已完成的服务。

### 2.2 回收人员

回收人员账号由社区管理员维护。回收人员登录后可以查看分派给自己的任务、确认或拒绝任务、更新回收进度，并登记实际回收结果中的数量和重量。

### 2.3 社区管理员

社区管理员登录后台后，可以管理居民和回收人员账号、维护回收品类、审核和分派订单、处理取消申请及异常订单、查看业务统计数据。

## 3. 功能结构

系统功能分为以下模块：

1. 账号与个人信息管理；
2. 回收品类查询与管理；
3. 回收地址管理；
4. 回收申请与订单管理；
5. 回收任务管理；
6. 回收结果登记与居民确认；
7. 服务评价；
8. 用户及人员管理；
9. 业务统计查询。

## 4. 详细功能需求

### 4.1 账号与个人信息管理

#### 4.1.1 居民注册

居民可以通过注册页面创建个人账号。注册时填写系统要求的账号信息，例如用户名、密码、姓名及联系电话。注册不需要手机验证码。

系统应校验必填项和账号唯一性。信息缺失、账号已存在或格式不符合要求时，系统应提示用户修改。注册成功后，居民可以使用该账号登录。

#### 4.1.2 用户登录与退出

居民、回收人员和管理员均可通过各自账号登录系统。系统根据账号身份开放相应功能。登录信息验证失败时，系统提示登录失败且不进入系统功能页面。用户可以主动退出登录。

#### 4.1.3 个人信息维护

登录用户可以查看和修改本人允许维护的个人资料。居民可以维护姓名、联系电话等信息；回收人员可以维护业务所需的个人联系方式。管理员可以查询用户和回收人员的基本资料，并对账号进行启用或停用管理。

### 4.2 回收品类查询与管理

#### 4.2.1 居民查询品类

居民可以查看当前开放回收的废旧家电品类及说明，包括品类名称、回收要求和品类状态等。居民提交申请时，只能选择当前启用的品类。

#### 4.2.2 管理员维护品类

管理员可以新增、修改、查询、启用或停用回收品类。品类信息包括名称、说明及回收要求。已被订单使用的品类应保留历史关联信息，避免影响历史订单查询。

### 4.3 回收地址管理

#### 4.3.1 地址新增与维护

居民可以新增、修改和删除本人回收地址，并设置默认地址。地址信息包括联系人、联系电话、所在区域、详细地址及补充说明。

删除或修改地址时，系统应确保历史订单中的地址信息仍可查询。

#### 4.3.2 地址选择

居民提交回收申请时，应选择一个有效回收地址。系统应在订单中保存本次预约使用的地址信息，便于回收人员执行任务和查询历史订单。

### 4.4 回收申请与订单管理

#### 4.4.1 提交回收申请

居民可以在线提交废旧家电回收申请。申请信息包括：

- 回收品类；
- 预计回收数量；
- 家电状况描述；
- 上门回收地址；
- 期望预约时间；
- 联系方式；
- 补充说明（选填）。

本期不要求上传家电图片。居民提交前应确认填写信息。申请成功后，系统生成唯一订单编号，并将订单状态设为“待审核”。

#### 4.4.2 居民查看订单

居民可以查看本人提交的订单列表和详情。列表展示订单编号、提交时间、预约时间、品类摘要和当前状态；详情展示申请信息、状态变化及处理记录。居民只能查询本人提交的订单。

#### 4.4.3 居民取消订单

居民可以取消处于“待审核”或“待分派”状态的订单。取消后，系统记录取消操作及时间，并将订单状态更新为“已取消”。

订单分派给回收人员后，居民不能自行取消。如需取消，居民应联系管理员，由管理员核实并处理。订单已进入“回收中”或“待居民确认”状态时，居民不能直接取消，应由管理员按异常业务进行处理。

#### 4.4.4 管理员审核申请

管理员可以查询待审核订单并查看申请详情。管理员审核后可以：

- **审核通过**：订单进入“待分派”状态；
- **审核驳回**：填写驳回原因，订单进入“已驳回”状态。

系统记录审核结果、审核意见、审核人和审核时间。居民可以查看审核结果及驳回原因。

#### 4.4.5 管理员分派订单

管理员可以将审核通过的订单分派给回收人员。分派成功后，系统记录回收人员、分派人和分派时间，订单状态变为“待接单”。管理员可以查询分派结果，并对尚未确认的订单重新分派。

### 4.5 回收任务管理

#### 4.5.1 回收人员查询任务

回收人员可以查看分派给自己的任务。任务信息包括订单编号、预约时间、回收地址、家电品类、预计数量以及居民联系人和联系电话等执行任务所需信息。回收人员只能查看分派给自己的任务。

#### 4.5.2 确认或拒绝订单

回收人员收到分派订单后，必须确认是否接单：

- 确认接单后，订单状态变为“已接单”；
- 无法执行任务时，可以拒绝接单并填写原因，订单进入“待重新分派”状态，交由管理员处理。

系统记录操作人、操作时间及拒绝原因。管理员可以重新分派订单或联系居民调整预约。

#### 4.5.3 更新回收进度

回收人员确认接单后，可以在开始执行上门回收时将订单状态更新为“回收中”。完成回收后，回收人员登记实际回收结果并提交，订单进入“待居民确认”状态。

#### 4.5.4 异常任务处理

若出现居民无法联系、地址错误、预约时间冲突或其他影响回收的情况，回收人员可以提交异常说明。管理员查看异常信息后，可以联系相关人员并登记处理结果。系统保留异常原因及处理记录。

### 4.6 回收结果登记与居民确认

#### 4.6.1 回收人员登记结果

完成上门回收后，回收人员登记实际回收情况，内容包括：

- 实际回收品类；
- 实际回收数量；
- 实际回收重量；
- 回收完成时间；
- 处理备注（选填）。

系统不登记回收金额。回收人员提交结果后，系统保存登记人和提交时间，并将订单状态更新为“待居民确认”。

#### 4.6.2 居民确认结果

居民可以查看回收人员登记的实际回收品类、数量和重量，并确认回收结果。居民确认后，订单状态变为“已完成”，系统记录确认人和确认时间。

如居民对登记结果有异议，可以提交说明并由管理员处理。管理员可以记录处理意见及最终处理结果；处理完成后，居民再次确认，或由管理员按业务处理规则完成订单。

### 4.7 服务评价

订单完成后，居民可以对本次回收服务进行评分和文字评价。居民只能评价本人已完成且尚未评价的订单。系统记录评价内容和提交时间，并防止同一订单重复评价。管理员可以查询订单评价。

### 4.8 用户及回收人员管理

管理员可以查询居民用户和回收人员信息，并按账号、姓名、联系电话或账号状态筛选。管理员可以启用或停用账号；停用账号后，该账号不能登录或执行相关业务操作。管理员可以新增、维护回收人员信息并为其分配账号。

### 4.9 订单管理

管理员可以按订单编号、居民用户、回收人员、订单状态和时间范围查询订单，并查看订单申请、审核意见、分派情况、任务进度、回收结果、居民确认情况、评价及异常记录。

对于拒绝接单、居民联系管理员提出取消、预约变更及回收异常等情况，管理员可以重新分派或登记处理结果。系统应记录审核、分派、重新分派、状态变更和异常处理等关键操作的操作人及时间。

### 4.10 业务统计查询

管理员可以按时间范围、回收品类和订单状态查询业务数据，包括：

- 回收申请总数；
- 各状态订单数量；
- 已完成订单数量；
- 各品类实际回收数量；
- 实际回收总重量。

统计结果用于社区日常业务管理。若系统提供图表，图表数据应与当前查询条件一致。本系统不统计回收金额。

## 5. 订单状态与流转规则

### 5.1 状态定义

| 状态 | 说明 |
|---|---|
| 待审核 | 居民已提交申请，等待管理员审核 |
| 待分派 | 管理员审核通过，尚未分配回收人员 |
| 待接单 | 管理员已分派，等待回收人员确认 |
| 已接单 | 回收人员已确认任务 |
| 回收中 | 回收人员正在执行上门回收 |
| 待居民确认 | 回收人员已登记实际回收结果，等待居民确认 |
| 已完成 | 居民已确认回收结果 |
| 已驳回 | 管理员驳回申请，订单不再进入回收流程 |
| 已取消 | 居民在允许状态取消，或管理员处理取消请求后取消 |
| 待重新分派 | 回收人员拒绝接单或任务无法执行，等待管理员处理 |
| 异常待处理 | 回收过程出现异常，等待管理员处理 |

### 5.2 主要状态流转

```text
居民提交申请
    ↓
待审核 ──管理员驳回──→ 已驳回
    │
    ├──居民取消──→ 已取消
    │
    └──管理员审核通过──→ 待分派
                              ├──居民取消──→ 已取消
                              └──管理员分派──→ 待接单
                                                   ├──回收人员拒绝──→ 待重新分派
                                                   │                      │
                                                   │                      └──管理员重新分派──→ 待接单
                                                   └──回收人员确认──→ 已接单
                                                                           ↓
                                                                         回收中
                                                                           ↓
                                                                    待居民确认
                                                                     ├──居民有异议──→ 异常待处理
                                                                     │                    └──管理员处理后返回确认
                                                                     └──居民确认──→ 已完成
```

### 5.3 状态操作权限

| 操作 | 执行角色 | 允许的状态 |
|---|---|---|
| 提交回收申请 | 居民 | 新建订单 |
| 审核通过或驳回 | 管理员 | 待审核 |
| 分派回收人员 | 管理员 | 待分派、待重新分派 |
| 确认或拒绝接单 | 被分派的回收人员 | 待接单 |
| 更新为回收中 | 回收人员 | 已接单 |
| 登记回收结果 | 回收人员 | 回收中 |
| 确认回收结果 | 订单所属居民 | 待居民确认 |
| 取消订单 | 居民 | 待审核、待分派 |
| 处理居民取消请求 | 管理员 | 已分派后的未完成订单，按实际业务核实 |
| 处理异常 | 管理员 | 异常待处理 |

系统应拒绝不符合当前状态或用户角色的操作，并向用户提示原因。

## 6. 功能权限要求

1. 居民只能管理本人资料、地址、回收申请、订单、结果确认和评价。
2. 回收人员只能查看和处理分派给本人的任务。
3. 管理员可以管理社区范围内的用户、回收品类和订单。
4. 用户停用后不得登录或继续执行业务操作。
5. 审核、分派、拒绝接单、状态变更、回收结果登记、居民确认和异常处理等操作，应记录操作人及操作时间。

## 7. 本期范围与后续扩展

### 7.1 本期核心功能

- 居民自行注册和登录，不使用手机验证码；
- 回收品类查询与管理；
- 居民地址管理；
- 回收申请提交与订单查询；
- 管理员审核、分派和订单管理；
- 回收人员确认或拒绝接单；
- 回收进度更新；
- 实际回收数量和重量登记，不登记金额；
- 居民确认回收结果后完成订单；
- 服务评价；
- 用户管理和基础业务统计。

### 7.2 暂不纳入本期的功能

- 手机验证码注册；
- 家电图片上传；
- 在线支付及退款；
- 回收金额登记；
- 短信或微信自动通知；
- GPS 定位和路线优化；
- 智能回收价格评估；
- 多社区、多级组织管理；
- 与第三方回收企业或监管平台对接；
- 投诉处理时限管理。
